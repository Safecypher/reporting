### E2E flow: push → drain → ingest → freshness → Slack

**Intact, no break.** `POST /api/push` accepts a file with no session and returns the
`reference` that later becomes `source_ref`; the `daily-drop-off` cron invokes
`/api/ingest/drain`; `ingestOne` calls the shared `ingest()` with push provenance, so pushed
files land through the same path as manual; post-drain, freshness is read via the *same*
`fetchFreshnessStripData` resolver the dashboard and `/uploads` strip use, so what Slack says
and what the screen shows cannot diverge; one `alert_runs` row is written per non-409 run
regardless of outcome, and Slack is posted only when something is wrong.
