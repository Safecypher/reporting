<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser upload → Route Handler | Uploaded bytes are untrusted; size and type are attacker-controlled |
| Route Handler → Postgres/Storage | Server writes use the secret key and must not be reachable without a session |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Denial of Service | Oversized/adversarial upload | mitigate | File-size cap in the Route Handler; PapaParse runs server-side on a bounded buffer; report files are small daily batches |
| T-05-02 | Elevation of Privilege | /api/ingest without session | mitigate | Handler reads the user via the server client and returns 401 when absent — independent of proxy.ts |
| T-05-03 | Information Disclosure | Secret key exposure | mitigate | `SUPABASE_SECRET_KEY` used only in `supabase-writer.ts`; never imported into `dropzone.tsx`/`upload-result.tsx` ('use client') |
| T-05-04 | Tampering | Double-count via re-upload | mitigate | sha256 dup-file short-circuit + DB `row_hash` UNIQUE ON CONFLICT DO NOTHING — idempotent at two layers |
| T-05-05 | Information Disclosure | Raw file public exposure | mitigate | Files written to the `public = false` `reports` bucket (Plan 03); served only via server client / signed URLs |
</threat_model>
