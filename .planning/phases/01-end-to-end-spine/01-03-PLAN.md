<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| authenticated client → Postgres | Client reads must be constrained by RLS; only the server (secret key) may write |
| any client → Storage objects | Uploaded report files must never be publicly reachable |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Information Disclosure | verifications / ingested_files tables | mitigate | RLS enabled on both; only `select` granted to `authenticated`; anonymous role has no access — independent of the proxy.ts gate |
| T-03-02 | Tampering | Ingested financial rows | mitigate | No insert/update/delete policy for `authenticated`; rows are effectively immutable to clients (DATA-07); corrections come via idempotent re-upload |
| T-03-03 | Information Disclosure | Raw report files in Storage | mitigate | `reports` bucket is `public = false` with an authenticated-only read policy; access via signed URLs / server client only |
| T-03-04 | Tampering | Double-counting via re-ingestion | mitigate | `row_hash` UNIQUE + ON CONFLICT DO NOTHING makes re-upload idempotent at the DB layer (D-06) — the one correctness decision Phase 2 inherits |
</threat_model>
