## This plan requires Supabase MCP access — dispatch it accordingly

**Executor subagents in this project do not have Supabase MCP access. The orchestrator must run
the applies, the live catalog queries and the end-to-end round trip itself.** Dispatching this
plan to a subagent without stating that division of labour will stall it at Task 1 having
committed a migration nobody applied — the exact failure this plan exists to close.

Two recorded hazards apply to how SQL is run here:

- Any SQL that writes real rows must be run as **one whole-body statement**, never
  statement-by-statement through `execute_sql`. Statement-splitting has previously dropped the
  surrounding transaction wrapper and deleted production data in this project.
- `.planning/state.json` write verbs regenerate the whole phases array; re-check statuses before
  committing anything that touches it.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `cron.job` command text → anyone with select on it | A readable catalog table; anything embedded there is effectively published to every database reader. |
| Postgres → the public drain URL | The job leaves the database and crosses the open internet to a URL anyone can also reach. |
| Migration file → git history | A secret committed here is permanent and unrotatable-by-deletion. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09-28 | Information Disclosure | cron secret in `cron.job` | high | mitigate | The secret is read from `vault.decrypted_secrets` by name at execution time; the command text holds only the lookup. A verify command asserts no assigned secret value exists in the migration or the env example. |
| T-09-29 | Information Disclosure | cron secret in git | critical | mitigate | The `vault.create_secret` call ships commented out with no value; `.env.local.example` carries an empty placeholder; `.env.local` is gitignored. |
| T-09-30 | Spoofing | anyone can POST to the public drain URL | high | mitigate | The route requires the shared secret and fails closed when the variable is unset; the mutex bounds the damage of a flood to one concurrent run. |
| T-09-31 | Denial of Service | repeated unauthenticated drain calls | medium | accept | Each is a cheap 401 before any Storage or database work. Edge rate limiting is outside this phase and is recorded as an assumption rather than silently assumed away. |
