| Property | Value |

## Screen Contracts

### 1. `/settings/senders`

**Page shell:** clone `/settings/general`'s structure exactly — `PageHeader` (eyebrow "Settings",
h1 "Push credentials" or "Senders", one-line description), an async Server Component body inside
`<Suspense fallback={<LoadingState />}>`, an `ErrorState` branch on any query error. Add
`{ href: "/settings/senders", label: "Senders" }` to `SETTINGS_ITEMS` in
`components/app-shell/settings-nav.tsx` (resolves CONTEXT.md's open "own sidebar entry vs
nested" discretion point — nested under the existing Settings group, consistent with General and
Pricing).

**Section order (top to bottom), separated by `Separator`:**

1. **Mint form.** `Label` "Sender name" + `Input` (Zod: required, trimmed, 1–100 chars). Below the
   input, a row of `Button variant="outline" size="sm"` chips — one per distinct sender name
   already present in `push_credentials` (e.g. "TSYS", "Bit Addict") — clicking one fills the
   input with that exact string. This exists specifically to prevent a typo (e.g. "Tsys" vs
   "TSYS") from silently creating a second, disconnected sender identity, since `sender` is
   deliberately not unique/FK-constrained (D-02). Submit button: "Issue credential"
   (`variant="default"`, accent color).

2. **Token reveal (on successful mint only) — a `Dialog`, not a toast.** A toast is wrong here: it
   auto-dismisses, and this is a show-once secret. Binding rules:
   - `onInteractOutside` and `onEscapeKeyDown` both call `event.preventDefault()` — this dialog
     cannot be dismissed by clicking outside or pressing Escape. Do not render Dialog's default
     `X` close affordance either.
   - Content: warning banner (`--warning` tokens, not `--destructive`) with the copy above; a
     read-only, monospace, full-width `Input` containing the complete token (selectable, not
     truncated); a "Copy token" `Button` beside it (`navigator.clipboard.writeText`, same pattern
     as `drill-sheet.tsx`'s `handleCopyLink`) → toast "Token copied".
   - The only way to close: **"I've saved it — done"** button. Clicking it closes the dialog and
     fires the "Credential issued for {sender}." toast.

3. **Credentials list.** One row per credential (never collapsed to one row per sender — that is
   the "naive" design the phase brief explicitly warns against). Table columns: Sender | Prefix |
   Created | Last used | Status | (Revoke action).
   - **Sort:** sender name ascending, then `created_at` descending within each sender — this
     keeps a sender's tokens visually adjacent without needing a separate grouped-header table
     layout.
   - **Sender cell:** `truncate max-w-[200px]` with a native `title` attribute holding the full
     string, so an unusually long/typo'd sender name degrades gracefully instead of breaking the
     table layout.
   - **Prefix cell:** monospace, e.g. `sc_live_a3f2b9c1…` — exactly what D-04 requires, never the
     full token.
   - **Last used cell:** `en-GB` medium-date/short-time format (matches `AuditLog`/
     `UploadsHistoryTable` precedent) when non-null; when null, render **"Never used yet"** in
     `text-muted-foreground italic` — this null state is load-bearing: during a rotation, a
     newly-minted token reading "Never used yet" tells the operator the sender hasn't switched to
     it, while the old token's recent "Last used" timestamp tells them it's still the active one.
   - **Status cell:** `Badge` — "Live" (`--success` tokens) or "Revoked" (neutral outline —
     `border-border bg-muted text-muted-foreground`, same treatment as the reconciliation
     "No report received" badge; revocation is not itself an alarm, it's the expected end state
     of a rotation). Revoked credentials stay in the list (never deleted from view) — this is the
     audit trail the milestone's "we manage our own destiny" thesis depends on.
   - **Rotation-in-progress signal:** when a sender has more than one row with Status "Live"
     simultaneously, render a small neutral outline `Badge` reading **"Rotating"** immediately
     after that sender's name, on every one of that sender's live rows. Neutral tokens only
     (never warning/destructive) — a rotation in progress is expected, healthy behaviour per D-02,
     not a problem.
   - **Revoke action:** only rendered on Live rows. `Button variant="destructive" size="sm"`
     "Revoke" → `Dialog` (clone `components/pricing/delete-tier-set.tsx`'s controlled-open +
     `useTransition` + toast pattern exactly) with the copy specified above, including the
     sole-live-credential escalation line when applicable.
   - **Empty state:** "No push credentials yet" / "Issue one to let TSYS or Bit Addict push
     reports automatically…" (see Copywriting Contract) — rendered in place of the table, same
     dashed-border treatment as `UploadsHistoryTable`'s empty state.

4. **Change history.** Reuse `AuditLog` verbatim with
   `emptyMessage="No credential changes yet."`, `AUDIT_ROW_CAP = 50`, and the same
   "Showing the 50 most recent changes" overflow caption — byte-identical pattern to
   `/settings/general` and `/settings/pricing`.

### 2. Uploads-history table extension (`/uploads`, `components/upload/uploads-history-table.tsx`)

The table becomes a client component (it needs local expand/collapse state for D-17 — see below)
fed by a Server Component that now runs a union query over `ingested_files` (joined through
`push_credentials` for the sender name, D-15) and `push_rejections` (D-16), interleaved by
timestamp descending.

**Column changes:**
- **New "Source" column**, inserted between "File" and "Uploaded": renders the sender name per
  D-15 — `"TSYS"`, `"Bit Addict"`, or `"Manual — {uploader email}"`. If the uploader's email
  cannot be resolved (no email-resolving view currently exists in this codebase — the same gap
  `/settings/pricing`'s audit log already documents and accepts), fall back to
  **"Manual — unknown user"**, never a raw UUID — a UUID is meaningless to the ~3 people reading
  this table and would look like a bug, not a known gap.
- **Accepted / Duplicates / Rejected count cells:** change `?? 0` to `?? "—"` (em dash,
  `text-muted-foreground`). This is a binding correction, not cosmetic — a delivery-rejection row
  has no row counts at all (nothing was ever parsed), and rendering `0` for all three implies "we
  processed this file and found nothing," which is a different and false claim from "this file
  was never parsed."

**Row interleaving (D-16):**
- Delivery rejections render as ordinary rows in the same table, sorted chronologically alongside
  real uploads (by rejection `timestamp` vs `uploaded_at`) — never a separate section or a second
  table.
- **File cell** for a rejection row: the rejected filename (monospace, matching existing style),
  with the rejection **reason** shown directly beneath it in `text-xs text-muted-foreground` —
  the reason is exactly as important as the filename for a rejected row and must not require a
  click to see.
- **Source cell:** the sender name directly from `push_rejections.sender` (rejections are always
  push-originated — this column never reads "Manual" on a rejection row).
- **Status cell:** `StatusBadge`'s new fourth branch, **"Delivery rejected"**, using the same
  `--destructive` tokens as the existing "Failed" branch (D-16's "existing failed-state styling")
  but distinct copy — see Copywriting Contract for why the label must differ from "Failed".
- **Count cells:** all three render `—` (see above).

**Empty-state correction (binding rule):** the `files.length === 0` check that currently gates
the empty state must become a check on the **combined** interleaved list length. A morning where
every file was delivery-rejected and zero real uploads exist must show those rejection rows, not
the "No uploads yet" empty state — showing the empty state there would be exactly the kind of
silent gap this milestone exists to eliminate.

**Row detail expand (D-17):**
- A chevron/disclosure affordance appears in a new leading icon-only column, **only on rows that
  have a non-null `source_ref`** — i.e. push-originated `ingested_files` rows. Manual uploads
  (`source_ref` is always null) and delivery-rejection rows (never had a `source_ref` — nothing
  was ever written to storage, structural checks failed first) render no affordance in that
  column at all, not a disabled one — there being nothing to show is not itself a state worth
  signalling.
- Use the existing `#arrow-right` sprite symbol, rotated 90° on expand, exactly matching
  `components/app-shell/settings-nav.tsx`'s collapsible-chevron treatment
  (`transition-transform motion-reduce:transition-none [state]:rotate-90`) — do not add a new
  chevron/caret icon.
- Clicking the chevron (or the row) toggles a detail sub-row directly beneath it, inset with
  `bg-muted/50`, containing a single labelled field: "Source reference" + the `source_ref` value
  in monospace with a "Copy" button (same clipboard pattern as the token-reveal dialog). This is
  an in-place expand, not a `Sheet` — a single opaque path string does not warrant an overlay
  context switch on a table read "daily at speed."
- Only one row expanded at a time is not required — independent per-row toggle state is fine
  (simplest `useState<Set<string>>` of expanded row ids).
