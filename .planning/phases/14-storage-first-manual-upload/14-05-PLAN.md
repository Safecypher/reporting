<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| inbox objects to the daily drain | objects written by browsers (manual/) and by push senders, processed with the secret key |
| secret-key Storage list to the rendered /uploads page | server-only data crossing into HTML |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-14-21 | Tampering | drain and claim processing the same object concurrently | medium | mitigate | 15-minute grace for manual/ objects from created_at (key timestamp fallback); content-hash dedup and the Phase 13 processing lease as further layers |
| T-14-22 | Denial of service | large or many abandoned manual objects pushing the drain past its ceiling, losing the alert_runs evidence row | medium | mitigate | MANUAL_DRAIN_BYTE_BUDGET per run (at least one object), manual prefix sorted after every push prefix, XLSX cap and size guards upstream (14-01, 14-02); deferred objects stay visible on /uploads |
| T-14-23 | Information disclosure | other users' unclaimed file names on /uploads | low | accept | internal team tool where every user already sees every upload in the history table; only name, uploader email and timestamps are shown |
| T-14-24 | Information disclosure | the secret-key client leaking into a client component | high | mitigate | listing runs in the server page; the presentational component has no "use client" and no Supabase import (grep gate); buildSecretClient stays server-only |
| T-14-25 | Spoofing | a drained manual file attributed to the wrong uploader | medium | mitigate | uploaded_by comes only from the server-minted key (parseManualObjectKey), never from a request body; an unparseable key records uploaded_by null rather than guessing |
| T-14-SC | Tampering | npm installs | high | mitigate | nothing installed |
</threat_model>
