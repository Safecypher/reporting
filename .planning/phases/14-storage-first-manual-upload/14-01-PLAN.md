<objective>
Build the storage-first manual upload spine end to end, server side, proven by a test that drives
the real route handlers and the real supabase-js signed-upload call.

The tracer (Task 1) carries ONE CSV through every server layer this phase introduces: the mint
route chooses an unguessable flat inbox key and returns a signed upload token; the browser-side
supabase-js `uploadToSignedUrl` call lands the bytes in the `inbox` bucket; the claim route reads
them back, authorises the key against the session, hashes and classifies them through the
existing `claimFile`, fires the Phase 13 background trigger and answers 202. Task 2 adds the
size guards, the not-found/double-claim calm path, and the edge-case tests for the key codec,
the mint route and the claim core.

Purpose: D-01, D-02, D-04, D-07, D-08, D-14, D-15, D-17 (and D-03: no billing gate). This is
the path every manual upload will take once 14-04 wires the dropzone onto it; the dropzone keeps
calling the old route until then, so nothing user-visible changes in this plan.

Output: two new routes, the shared per-object module, the pure claim core, and their tests.
</objective>

<assumption_delta_decision>
Primary noun: the **inbox object**. The `inbox` bucket gains a second source (manual uploads
under `manual/`, alongside push deliveries under `{credentialId}/`), and the per-object ingest
step gains a second caller (the claim route, alongside the drain). The source is discriminated by
key shape alone: a key starting `manual/` is a manual upload; anything else keeps the push
branch exactly as it is today.

Decision: **promote**. The drain route's private `ingestOne` closure is promoted to the shared
`ingestInboxObject` in `lib/ingestion/inbox-object.ts` with both branches, rather than adding a
second, parallel manual implementation alongside it. Rationale: D-08 says the claim step IS the
drain's per-object step run for one object; two implementations would drift (provenance, writer
lifetime, trigger handling). 14-05 switches the drain onto it and adds the invariant test
"every inbox object, push or manual, round-trips through the one shared per-object function".
Between this plan and 14-05 the drain still runs its original closure; that window is one wave
long and is closed by 14-05 Task 1, not accepted as lasting debt.
</assumption_delta_decision>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser to mint route | untrusted JSON (fileName, size) from a signed-in session |
| browser to Supabase Storage | the signed PUT carries attacker-controllable bytes, type and length |
| browser to claim route | untrusted JSON (path, fileName); the path names an object to process |
| claim route to Storage and ingested_files | secret-key client; bypasses RLS, so authorisation is the route's job |
