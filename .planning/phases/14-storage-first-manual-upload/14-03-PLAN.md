## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PostgREST (anon/authenticated) to public.ingested_files | browser-held keys reach the table through the Data API |
| browser to Storage inbox | signed uploads land objects whose size Storage must bound |
| orchestrator to the live database | MCP apply_migration and execute_sql run with elevated rights |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-14-12 | Elevation of privilege | default table-wide grants on ingested_files | medium | mitigate | 0051 revokes all from anon and authenticated at table level and grants SELECT back to authenticated only |
| T-14-13 | Tampering | a privilege change that reports success and does nothing | high | mitigate | table-level form (never column-level, per 0042); the read-only oracle raises on any surviving privilege and is run through MCP after apply |
| T-14-14 | Denial of service | losing authenticated SELECT breaks /uploads and the freshness views | medium | mitigate | the grant-back is part of the same migration; the oracle raises if authenticated lacks SELECT; a deployed smoke of /uploads and /api/ingest/status follows |
| T-14-15 | Denial of service | oversized objects reaching the inbox | medium | mitigate | 0052 bucket limit at 104,857,600 after the global limit is raised; the claim's own size guards (14-01) are the backstop |
| T-14-16 | Denial of service | a MIME allow-list rejecting real CSV uploads | low | mitigate | allowed_mime_types explicitly null; the claim sniffs bytes instead |
| T-14-SC | Tampering | npm installs | high | mitigate | this plan installs nothing |
</threat_model>
