# Phase 3 — UI Design Contract

> Visual and interaction contract for Revenue, SLA & Drill-down. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope:** Revenue view (REV-01/02, DATA-03), Pricing admin (ADMIN-01), SLA view (SLA-01), and the generic URL-synced drill-down Sheet (DASH-03).
>
> **Standing contract:** This phase does **not** invent a new visual language. It is a **strict extension** of `.planning/phases/01-end-to-end-spine/01-UI-SPEC.md`, which remains the single source of truth for brand tokens (`design-system/colors_and_type.css`), the shadcn→brand mapping, the 4-state contract, and copy voice. Only what is new to Phase 3 (money formatting, tier breakdown, SLA reference line, pricing form, drill-down Sheet) is specified below. Where this document is silent, defer to 01-UI-SPEC.md.

---

## Design Aesthetic (Decision)

**Decision:** Unchanged from Phase 1 — clean, professional, trustworthy internal-tool aesthetic, Cypher Blue as the single lead, 1pt hairlines over shadows, pill buttons, calm neutrals so colour carries meaning. Money and SLA are the two new "meaning" domains this phase adds: money uses tabular numerals and a single accent per figure; SLA breach uses the brand `--error`/`--warning` tokens, never a second bespoke red.

**Rationale:** Phase 3 sits directly beside the Verifications view in the same nav and must read as the same product, not a bolted-on module — especially because Phase 4's reconciliation view will sit beside these two and inherit the same drill-down Sheet.

## Visual Hierarchy & Focal Points

| Screen | Primary anchor (focal point) | Secondary anchors | Tertiary / chrome |
|--------|------------------------------|-------------------|-------------------|
| **Revenue view** | The **total-revenue KPI** (`.metric` treatment, Cypher Blue, largest number on the page, USD-formatted) at the top | The revenue-over-time chart (same size/position convention as the Verifications chart) | Per-tier breakdown (table or stacked bar, see D-07) below the chart; `ViewControls` toggle; freshness badge |
| **SLA view** | The **average-duration trend chart** with the 750ms `ReferenceLine` — the line itself is a visual anchor (dashed, `--fg-3` neutral, labelled "750ms SLA") | The breach table beneath the chart (drillable rows in `--error`/`--warning`) | `ViewControls` toggle; freshness badge; breach-count KPI (secondary, smaller than the Revenue-view total) |
| **Pricing admin** | The **tier editor** (ordered list of threshold+rate rows, add/remove controls) — the single working surface on the page | The effective-from date picker/selector for the tier set being edited | The audit/change-log list (who/what/when), positioned below the editor as a secondary reference, not competing for attention |
| **Drill-down Sheet** (cross-cutting) | The **TanStack Table of raw rows** filling the Sheet body — this is the entire reason the Sheet exists | The Sheet header stating what's being drilled ("Verifications on 14 Aug 2026, failed") and a close affordance | A "copy link" affordance next to the header (URL already reflects the filter — D-10) |

**Money and SLA both borrow the brand `.metric` treatment for their single headline KPI** (Total revenue; Breach count), consistent with Phase 1's Total-verifications treatment — one accent-teal underline maximum per screen, reserved for that headline stat only.

## Radius & Shadows

Unchanged from 01-UI-SPEC.md: `--radius-pill` for all buttons (including "Add tier" / "Remove tier" row controls), `--radius-lg` for cards/panels, 1px `--rule` hairlines as the default surface treatment. The drill-down Sheet uses `--shadow-md` (the one place, alongside dialogs, where elevation is intentional — a slide-over must visually separate from the page behind it).

## Typography

Unchanged base scale from 01-UI-SPEC.md. Phase-specific applications:

| Role | Family / Weight | Size | Line height | Usage |
|------|-----------------|------|-------------|-------|
| Metric / KPI | Poppins 700 (`.metric`) | 48px | 1.0 | Total revenue (USD), breach count — same treatment as Total verifications |
| Money in tables/breakdowns | Brand mono (`--font-mono`), tabular-nums | 14–16px | 1.5 | Per-tier revenue amounts, breach durations, any currency or duration value in a table cell — **all money and duration figures are tabular/mono, never proportional Poppins**, so digits align vertically |
| Tier row label | Poppins 500 | 14px | 1.5 | "Tier 1", threshold values in the pricing editor |
| Audit log entry | Poppins 300 / mono for timestamp | 12–14px | 1.5 | "{user} changed Tier 2 rate from $0.08 to $0.09 — {timestamp}" |
| Sheet header | Poppins 500 | 20px | 1.25 | Drill-down Sheet title |

**Currency formatting rule (binding for executor):** USD, `Intl.NumberFormat('en-US', { style: 'currency', currency: 'USD' })`, always 2 decimal places at display, computed from exact minor-units/NUMERIC and **rounded exactly once at the display boundary** (L-01). Never format an intermediate per-tier value and re-sum the formatted strings — sum first in minor units, format last.

## Color

Unchanged palette from 01-UI-SPEC.md (60/30/10, Cypher Blue lead, brand semantic tokens). Phase 3 additions to the **reserved-for** list:

| Role | Token | Value | Usage (Phase 3 additions) |
|------|-------|-------|----------------------------|
| Lead accent (~10%) | `--cypher-blue` | `#382aff` | + Revenue-view total KPI, revenue chart primary series, active Revenue/SLA nav items |
| SLA breach / error | `--error` | `#c1121f` | Chart points above 750ms; breach-table rows/badges; "over SLA" state |
| SLA near-threshold (optional) | `--warning` | `#8a6d00` | **Discretion:** if the planner wants a pre-breach amber zone (e.g. 600–750ms) — not required by SLA-01, which only demands breach highlighting. Default: skip the warning zone in v1; only red breach vs neutral pass. Revisit if user testing shows value. |
| Reference line | `--fg-3` (neutral) | `#8a8a8d` | The 750ms `ReferenceLine` itself — dashed, labelled, never the same colour as a data series (must read as a threshold, not a trend line) |
| Audit trail meta | `--fg-3` | `#8a8a8d` | "who/what/when" secondary text in the pricing audit log |

**Cypher Blue is NOT used for the SLA breach state** (that would visually contradict "breach = bad"). Breach is always `--error` red, consistent with the brand's Discrepancy/breach/error row in the Data-Visualisation Palette table (01-UI-SPEC.md).

**Revenue chart series:** single series (total revenue), Cypher Blue, matching the Authenticated series treatment. The per-tier breakdown (D-07) uses a sequential single-hue ramp of Cypher Blue tints (`--blue-tint-08` lightest → `--cypher-blue` darkest) to show tier order without introducing new hues — tiers are ordinal, not categorical, so a single-hue ramp is more honest than arbitrary colours.

**Destructive actions in this phase:** Removing a tier row **before saving** is a local, undoable form edit — no confirmation needed (nothing is persisted yet). There is **no delete of a saved/historical tier set** (D-04: past tier sets are immutable history, only new effective-dated sets are added) — so there is no destructive *persisted* action in this phase. If the planner discovers a need to void/cancel a future-dated tier set before its effective date arrives, that would need an `AlertDialog` confirmation naming the exact effective-date and rate being cancelled — flag to planner as an open question, not decided here.

## Interaction & State Contract (trust-critical)

Every data surface (Revenue, SLA, and the Sheet) implements the **same 4-state contract as Phase 1** — no exceptions:

1. **Loading** — skeleton placeholders, never a blank flash (same shape as `LoadingState` in `verifications/page.tsx`).
2. **Empty** — explicit empty-state copy with a next action (link to Upload). SLA's breach table has a **distinct fifth micro-state**: populated-overall but zero breaches — phrase as good news, not as an empty/error state (see Copywriting).
3. **Populated** — data with `Data as of last import: {timestamp}` freshness badge and the data-window caption, matching Phase 1 placement exactly (same `PageHeader` component, reused not reinvented).
4. **Error** — explicit error copy, never swallowed; a revenue-computation failure (e.g. no pricing tiers configured for the period) is an **error state, not a silent zero** — "$0 revenue" must never be displayed as if it were a real answer when it's actually "tiers not configured."

**Drill-down Sheet contract (D-10/D-11, binding on all consumers incl. Phase 4):**
- Every summary metric (verification counts, revenue KPI, per-tier amounts, SLA breach rows) is clickable and opens the Sheet.
- Clicking sets URL query params (e.g. `?drill=verification&date=2026-08-14&authenticated=false`); the Sheet's open/closed state and filter are derived from the URL, not component state, so a shared link reopens the same drilled view on load.
- Closing the Sheet removes the drill params from the URL (back to the clean view URL) — use replace-state, not push-state, to avoid polluting browser history with every drill open/close.
- The Sheet always shows what filter produced its contents in the header (never an unlabelled table).

**Pricing admin contract:**
- Field-level validation (Zod) shows inline errors before submit attempt where possible; submit-time validation (contiguity/ordering) shows a banner-level error above the form.
- On successful save, the change appears immediately at the top of the audit/change-history list (optimistic or refetch — planner's call) with the acting user's email and timestamp.
- Revenue views must reflect the new tier set on next load **without any re-ingestion trigger** (REV-02) — this is a query-time join against the effective-dated tier set, not a cached/precomputed value.

Focus rings (brand `--focus-ring`) visible on all interactive elements, including Sheet-triggering clickable metrics (must be keyboard-operable, not click-only).
