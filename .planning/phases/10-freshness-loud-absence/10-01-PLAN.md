    **A. `supabase/migrations/0046_freshness_spine.sql`** — eight steps, in this order: six
    object definitions (1–6), then grants (7), then the seeded rows and their rationale block (8).
    Each object carries a header comment restating "coverage is evidence from the data, never a
    filename":

    1. `v_dcvv_coverage_daily`, `with (security_invoker = on)`. Copy
       `v_verification_coverage_daily` from `0022` idiom-for-idiom, substituting `dcvv_fetches`
       and the quoted `"timestamp"` column: a `file_spans` CTE taking
       `min(("timestamp" at time zone 'UTC')::date)` and `max(…)` per `source_file_id` with
       `where "timestamp" >= '2026-08-13T00:00:00Z'` applied BEFORE the min/max, then
       `cross join lateral generate_series(span_start, span_end, interval '1 day') as gs(day)`,
       emitting `(day date, source_file_count bigint)`. The column really is named `timestamp`
       and must be quoted everywhere it appears.

    2. `report_sources` — `report_type text primary key`,
       `expected_cadence text not null check (expected_cadence in ('daily-business','daily','none'))`,
       `stale_after_hours int not null check (stale_after_hours >= 0)`,
       `enabled boolean not null default true`, `updated_by uuid references auth.users(id)`,
       `updated_at timestamptz not null default now()`. RLS enabled; policies
       `report_sources_select_authenticated` (select, to authenticated, using true) and
       `report_sources_update_authenticated` (update, to authenticated, using true with check
       true) — L-04, no RBAC, D-13 requires audit not restriction. Deliberately NO insert and
       NO delete policy: the six rows are migration-seeded and can never be created or removed
       by a client.

    3. `report_sources_audit` — `id bigint generated always as identity primary key`,
       `changed_by uuid references auth.users(id)`, `changed_at timestamptz not null default now()`,
       `report_type text not null`, `old_expected_cadence text`, `new_expected_cadence text`,
       `old_stale_after_hours int`, `new_stale_after_hours int`, `old_enabled boolean`,
       `new_enabled boolean`, `summary text not null`. RLS enabled, select-to-authenticated
       only, no insert/update/delete policy for any client role. Then
       `fn_report_sources_audit()` — `language plpgsql`, `security definer`,
       `set search_path = public` — building `summary` from a `summary_parts text[]` naming only
       the fields that actually changed (the `0035` idiom), falling back to
       `'Source settings saved with no change to a tracked field'` when the array is empty, and
       stamping `auth.uid()`. Attach `trg_report_sources_audit after update on report_sources

       `revoke execute on function fn_report_sources_audit() from public, anon, authenticated;`
       — PostgREST exposes any public-schema function as an RPC and a trigger fires as the
       function owner regardless of grants.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → PostgREST (`authenticated` role) | Any signed-in internal user can read every view and table this migration creates, and can UPDATE `report_sources`. RLS and grants are the only control. |
| PostgREST → SECURITY DEFINER function | `fn_report_sources_audit()` runs as its owner; PostgREST exposes any public-schema function as a callable RPC unless EXECUTE is revoked. |
| view → underlying table RLS | A view created without `security_invoker` executes as its owner and silently bypasses every policy on the tables beneath it. |
