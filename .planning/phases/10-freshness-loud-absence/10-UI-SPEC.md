phase:

| Token | Value | Usage |
|-------|-------|-------|
| `--space-1` | 4px | Icon-to-label gaps, badge internal padding |
| `--space-2` | 8px | Compact spacing (table cell padding) |

| `--space-6` | 32px | Layout gaps between major page sections (`gap-6`) |

sm:grid-cols-3 lg:grid-cols-6` wrapper, so all six read as one row on a wide screen and wrap
predictably on narrow ones.

| Role | Value | Usage |
|------|-------|-------|

| Accent (10%) | `var(--primary)` (`#382aff`) | Reserved for: focus rings, in-page links, and the Save buttons on `/settings/sources` (`variant="default"`). **Never** used for any freshness badge, current or otherwise — accent means "primary action," not "healthy." |
| Success | `var(--success)` (`#0a7a4b`) | The "Current" freshness badge only. |
| Warning | `var(--warning)` (`#8a6d00`) | The "Overdue" freshness badge, and the inbox-stuck sentence line (D-09) — an operational hiccup that needs attention but is not itself a data-integrity failure, the same severity tier as "Overdue." |
| Destructive | `var(--destructive)` (`#c1121f`) | The "Failed to parse" freshness badge only. |
| Neutral outline | `border-border bg-muted text-muted-foreground` | The "No report received" AND "Disabled" badges (both reuse `StatusBadge`'s `no_source_data` branch — see Copywriting Contract for why these two facts, though visually identical, must never share the same label). |

**Density note (gap #5 — accessibility):** this strip is the densest colour use in the app —
six badges, up to five distinct states, on one screen. The binding rule, already established by
`StatusBadge`'s own `no_source_data` comment and quick task `260823-l9c`: **the text label
always carries the meaning.** No freshness state may ever be conveyed by badge tint alone, an
icon alone, or row-background tint alone. Concretely for this phase:
- Every badge renders its state as a word ("Current"/"Overdue"/"No report received"/"Failed to
  parse"/"Disabled") — never a bare coloured dot or icon-only chip.
- The six source labels appear in the **same fixed order on every render** — Verification,
  Billing, DCVV, Card inventory, Removed cards, APIGEE stats (the phase's own canonical list
  order) — never re-sorted by status. A source that changes state must be found in the same
  visual slot as yesterday; sorting by severity would make the strip itself an obstacle to
  scanning for change, defeating "loud absence."
- The per-item caption (last-covered date, or "Arrived …") is a second, independent channel
  that repeats the state distinction in plain text, not merely decoration.

## Copywriting Contract

### Freshness strip (dashboard home + `/uploads`)

| Freshness state | `StatusBadge` branch | Label | Caption |
|---|---|---|---|
| Current | `ok` | "Current" | "Last covered {Ddd D Mon}" (e.g. "Last covered Fri 26 Sep") |
| Overdue | `needs_review` | "Overdue" | "Last covered {Ddd D Mon}" — **never** "Last seen" or "Uploaded" (D-01: the date is the latest *covered* business day, not an upload timestamp) |
| No report received | `no_source_data` | "No report received" | *(no caption rendered — see below)* |
| Failed to parse | `mismatch` | "Failed to parse" | "Arrived {Ddd D Mon, HH:mm}" — deliberately "Arrived," never "Last covered," since a failed file produced no coverage at all |
| Disabled | `no_source_data` | "Disabled" | "Monitoring off" |

**Binding precedence, evaluated in this order per source:**
1. `report_sources.enabled = false` → always **Disabled**, regardless of any underlying
   coverage or failure fact. (Gap #4: `v_source_freshness` only emits one row per *enabled*
   source per the design doc, so a disabled source has no row to read at all — the UI must
   look up `report_sources` independently for all six sources and treat "absent from
   `v_source_freshness`, present in `report_sources` with `enabled=false`" as Disabled, never
   as "missing" and never as "No report received.")
2. Otherwise, if the most recent `ingested_files` row for that report type has
   `status = 'failed'` → **Failed to parse**, regardless of whether an older covered day is
   still within threshold. An operator needs to know the last thing that happened for this
   source was a break, even if the strip would otherwise read green.
3. Otherwise, if `v_source_freshness.stale = true` → **Overdue**.
4. Otherwise, if a covered day exists and is not stale → **Current**.
5. Otherwise (no coverage has ever existed for this source, and the latest attempt, if any,
   did not fail) → **No report received**.

**"No report received" renders no caption at all** — never a fabricated date, never
"Uploaded: —," never a raw `null`. This is the same "absence as a first-class normal case"
discipline the `StatusBadge` `no_source_data` branch already documents: the badge label alone
states the fact; nothing beneath it should imply a date exists when none does.

**Inbox-not-draining line (D-09, locked):**
- Non-zero: **"{N} objects stuck in the inbox since {timestamp}"** — `{timestamp}` is the
  *oldest* stuck object's original delivery time, formatted `en-GB` medium-date/short-time
  (matches `CredentialsTable`'s "Last used" convention), e.g. "3 objects stuck in the inbox
  since 26 Sep, 06:14."
- Clean (zero stuck objects): the line is **absent entirely** — no "0 objects stuck," no
  collapsed empty row.
- Rendered in `text-sm font-medium text-[color:var(--warning)]` above the six-source grid,
  inside the same `Card`/`CardContent` — occupying the sentence slot `AlignmentStrip` already
  established (rollup sentence + per-item badge row), per D-09.

(neutral `border-border bg-muted text-muted-foreground` box, **not** a warning/error treatment — this is a known, tracked limitation, not something currently broken) |

Bare, not "Save {source}" — the row's own Source cell already states the noun in the same visual line, so the button's label doesn't need to repeat it (same reasoning as any inline per-row table action). Set `aria-label={`Save ${source} settings`}` on the `Button` so the noun is still present for assistive tech, which reads the label out of row context. |
| Per-row save success toast | "Saved {source} settings." |
| Per-row save error toast | "Could not save {source} settings — {error}." (row **stays in its edited state** so the change can be retried without re-entering it) |
| Empty state | *(not applicable — the table always shows exactly six migration-seeded rows; there is no zero-row state to design for)* |
| Error state | "Report sources could not be loaded." / "Try refreshing the page." |
| Change history | Reuse `AuditLog` verbatim, `emptyMessage="No source setting changes yet."`, `AUDIT_ROW_CAP = 50`, identical overflow caption to `/settings/senders` and `/settings/pricing`. |

**Destructive actions in this phase: none.** Disabling a source (toggling Enabled off) is
reversible with one more click and takes effect only on Save — it does not warrant a
confirmation dialog. This is a deliberate departure from Phase 9's Revoke pattern: revoking a
credential is a one-way trust removal; disabling freshness monitoring on a source is neither
one-way nor high-stakes, and gating it behind a dialog would train operators to click through
confirmations reflexively, weakening the signal Revoke's dialog is meant to carry.

### Slack notification body (D-11, locked shape — formatting mechanics are this phase's discretion)

Plain `text` payload (not Block Kit) — a 3–4 line grouped message does not need Block Kit's
layout primitives, and plain text is the smaller, simpler `pg_net` POST body for a PoC-stage
internal tool:

```
Overdue: verification (last covered Fri 26 Sep), dcvv (last covered Thu 25 Sep)
Failed to parse: billing (2 files)
Inbox: 3 objects stuck
```

One line per wrong-state group, omitted entirely when that group is empty; a trailing link to
`/uploads` on its own line. Never posted when every group is empty (D-12: silence means
healthy).

## Screen Contracts

### 1. `FreshnessStrip` (shared component — dashboard home + `/uploads`)

New file `components/dashboard/freshness-strip.tsx`, structured after `AlignmentStrip`:

```
<Card><CardContent className="flex flex-col gap-3">
  {stuckCount > 0 && <p>{inbox-stuck sentence}</p>}
  <div className="grid grid-cols-2 gap-x-4 gap-y-3 sm:grid-cols-3 lg:grid-cols-6">
    {sixSourcesInFixedOrder.map(source => (
      <div className="flex flex-col gap-1">
        <div className="flex items-center gap-1.5">
          <span className="text-xs font-medium uppercase tracking-[0.08em] text-muted-foreground">
            {source.label}
          </span>
          <StatusBadge status={...} label={...} />
        </div>
        {caption && <p className="text-xs font-light text-muted-foreground">{caption}</p>}
      </div>
    ))}
  </div>
</CardContent></Card>
```

- No outbound "View more" link (unlike `AlignmentStrip`'s "View alignment") — there is no third,
  deeper freshness page this phase; the two rendering locations (dashboard, `/uploads`) are
  themselves the whole picture.
- **No page-level empty state.** `report_sources` is migration-seeded with exactly six rows;
  the strip always has six items to render. The "No report received" badge on an individual
  item **is** that item's empty state — there is no "the whole strip is empty" case to design.
- **Loading:** `FreshnessStripSkeleton` — a `Card` containing a skeleton sentence-height bar
  (loading state doesn't yet know whether the inbox line will render, so it always shows the
  placeholder shape, same convention as `AlignmentStripSkeleton`) plus six `h-5 w-24`-ish
  skeleton chips in the same grid shape.
- **Error:** handled entirely by `TileErrorBoundary label="Freshness"` wrapping the component on
  both pages — renders "Freshness could not be loaded." with a "Try again" retry button, per
  the existing fallback contract in `tile-error-boundary.tsx`. No bespoke error UI needed inside
  `FreshnessStrip` itself.
