<objective>
Make an incomplete day loud: after the daily drain, check freshness, post exactly one grouped
Slack message when something is wrong, and record every run in `alert_runs` whether or not it
had anything to say.

Purpose: ROADMAP SC-4 and FRESH-04. "Silence means healthy" is the only alerting discipline
that survives more than a fortnight — but it has one failure mode, and `alert_runs` is the
answer to it: a broken notifier is otherwise indistinguishable from a healthy week.

Output: `lib/notify/slack.ts` (the composer and the bounded POST), the drain route extended
after `drainInbox` returns, and tests for both.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Next.js Node route → Slack (outbound, third party) | The route sends a composed message to an external service over the public internet and reads back an untrusted response body. |
| `process.env` → persisted row / log line | `SLACK_WEBHOOK_URL` is a bearer-equivalent secret: anyone holding it can post into the channel as this app. |
| pg_cron / pg_net → the drain route | The only authenticated caller, via the `DRAIN_CRON_SECRET` bearer check that already exists. Unchanged by this plan. |
| secret-key server client → `alert_runs` | Writes bypass RLS entirely. This is the only writer. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-09 | Information Disclosure | `SLACK_WEBHOOK_URL` | high | mitigate | Read only via `process.env` inside the Node route handler. Never passed to a client component, never returned from a Server Action, never written into `alert_runs`, never an argument to a `console` call. Gated by a grep assertion in Task 2 and by `postSlackAlert` never placing the URL in its return object. Not prefixed `NEXT_PUBLIC_`. |
| T-10-10 | Denial of Service | the outbound Slack POST | medium | mitigate | `AbortSignal.timeout(8000)` bounds the call well under pg_net's 60000ms wait, and `export const maxDuration = 60` matches the route's ceiling to that wait. A hung webhook costs 8 seconds, not the whole request. |
| T-10-11 | Repudiation | a silently broken notifier | high | mitigate | One `alert_runs` row per non-409 run, written BEFORE the post and updated with its outcome, carrying `posted`, `http_status`, bounded `response_body` and `error`. "Quiet because healthy" and "quiet because broken" are distinguishable by reading the table. |
| T-10-12 | Tampering | the untrusted Slack response body | low | mitigate | The response is read with `res.text()` and truncated to 500 characters before being persisted. It is never parsed as JSON, never evaluated, and never rendered as HTML. |
| T-10-13 | Denial of Service | alerting failure cascading into ingestion | medium | mitigate | Every alerting step is inside try/catch downstream of `drainInbox`; the route's status and `{ processed }` body are unchanged in every branch, so a Slack outage can never make a successful drain look failed or trigger a sender retry of a file that arrived fine. |
| T-10-SC | Tampering | npm/pip/cargo installs | high | mitigate | package-legitimacy gate + blocking human checkpoint for [ASSUMED]/[SUS].
