<objective>
Make a stuck upload visible on the page where someone would look for it.

This phase turns `pending` from a rare crash artefact into the normal intermediate state of every
upload. That creates a new failure mode — a file that enters `pending` and never leaves — and D-03
requires it be surfaced on two surfaces. This plan is the second: `/uploads` itself, for the person
reviewing days later with no Slack history to hand.

Purpose: ROADMAP SC-4 and INGEST-10. Five rows sat unnoticed before 2026-10-05, the oldest for three
days, and the plain Pending badge is exactly why nobody saw them.

Output: a pending-state derivation in `lib/upload/history.ts`, two new badge states in the uploads
history table, and the two columns the page must select to feed them.
</objective>

  <behavior>
    New cases in `lib/upload/__tests__/history.test.ts`, written BEFORE the code. Every existing case
    must still pass with its body unedited.

    `IngestedFileRow` gains `processing_started_at: string | null` and `processing_attempts: number`,
    and `CombinedHistoryRow` gains `pendingState: PendingState | null`, `pendingSince: string | null`
    and `processingAttempts: number | null`.

    `mergeHistory(uploads, rejections, emails, asOf)`:
    - a `done` upload row carries a null `pendingState` — the field is meaningful only for a pending row.
    - a `failed` upload row carries a null `pendingState`.
    - a rejection row carries a null `pendingState` and a null `processingAttempts`; a refusal at the door was never pending.
    - a `pending` row uploaded two minutes before `asOf` with no lease carries `pendingState: "processing"`.
    - a `pending` row uploaded three days before `asOf` with no lease carries `pendingState: "stuck"` and a `pendingSince` equal to its `uploaded_at`.
    - a `pending` row uploaded three days before `asOf` whose lease was taken ten seconds ago carries `pendingState: "processing"` — it is genuinely being worked on in this moment.
    - `processingAttempts` is carried through from the row for an upload and is null for a rejection.
    - the existing ordering, tie-break, source-label and count behaviour is unchanged for every one of these rows.

    `formatPendingCaption(row, asOf)`:
    - returns null for a row with no `pendingState` — there is nothing to caption.
    - for a processing row on its first attempt, returns null; a bare "processing" badge says enough and a caption that adds nothing is noise.
    - for a processing row on its third attempt, returns a caption naming the attempt number, so a file converging across chained attempts reads as progress.
    - for a row stuck since three days ago, returns a caption naming the duration in whole days.
    - for a row stuck since eight hours ago, returns a caption naming the duration in whole hours.
    - the caption never contains a raw ISO timestamp and never contains a negative duration, including when `asOf` is marginally before `uploaded_at` (clock skew between a server render and the stored value is real and must not render as "stuck for -1 hours").
  </behavior>

  <action>
    Extend `IngestedFileRow` with the two new columns and `CombinedHistoryRow` with the three derived
    fields. The row type is the shape the page's select produces, so adding the columns here is what
    makes the missing-column failure a type error rather than a silent degradation.

    Give `mergeHistory` a fourth parameter, `asOf: Date`. It is required, not defaulted to `new Date()`.
    A default would make the function read the clock, which is exactly what stops it being testable at
    a boundary and lets a server render and a later client re-render disagree about whether a row
    crossed the six-hour line. The caller passes one instant and every row in that render is resolved
    against it.

    Inside the upload-row mapping, call `resolvePendingState` from `lib/ingestion/pending-state.ts`
    with the row's status, uploaded-at, lease and attempt count, and the `asOf`. Carry the result,
    the `uploaded_at` as `pendingSince` when the state is stuck, and the attempt count. The rejection
    mapping carries nulls for all three — explicitly, not by omission, so the shape is uniform and the
    component never has to ask which kind of row it is holding.

    Importing from `lib/ingestion/pending-state.ts` here is deliberate and safe: that module is pure,
    has no Supabase or Next import, and is the single place the stuck threshold lives. The alternative
    — a second six-hour constant in this file — is precisely the drift that would let the page and the
    Slack alert disagree about what stuck means, and 10-03 established that discipline for the same
    reason on the freshness side.

    Add `formatPendingCaption(row, asOf)` returning `string | null`, next to `formatCount` and
    `sourceLabel`, because it is the same kind of rule: a presentation decision that must be testable
    without a DOM.

    For a processing row, caption only the attempt number and only when it is above one. For a stuck
    row, caption the elapsed time since `pendingSince` in whole days when that is at least one day, in
    whole hours otherwise, with correct singular and plural forms. Clamp the elapsed value at zero
    before formatting, so a row whose stored timestamp is marginally ahead of the render instant reads
    as the smallest duration rather than a negative one.

    Keep every string in this module rather than in the component — that is what this file is for, and
    the dropzone's copy already lives in its sibling `lib/upload/batch.ts` for the same reason.
  </action>

    Replace `StatusBadge`'s final fall-through branch. It currently renders a muted Pending badge for
    anything that is not done, failed or the rejection sentinel. It now takes the derived
    `pendingState` and renders one of two things.

    Processing: a muted, neutral badge — the same restrained treatment the current Pending badge has,
    because a file being worked on is not a problem and must not read as one. Reuse the existing
    `variant="outline"` with the muted-foreground class already there rather than introducing a new
    colour token; there is no new semantic here, only a new word.

    Stuck: the destructive treatment the Failed branch already uses — the same border, background and
    text tokens. This is deliberate and matches how the table already distinguishes a refusal from a
    parse failure: same visual weight, different label. A file stuck for three days is a problem of the
    same order as one that failed to parse, and inventing a third severity for it would be a
    distinction without a difference.

    Keep the branch order and the existing three branches byte-identical in behaviour. A row whose
    `pendingState` is null and whose status is none of the three known values still needs an answer —
    render the processing badge as the conservative default, never the stuck one. Guessing "stuck" for
    an unknown state would manufacture an alarm from missing information.

    Under the badge, render the caption from `formatPendingCaption` when it is non-null, in the small
    muted type the file-name cell already uses for a rejection's reason. One pattern for a
    secondary explanatory line on this table, not two.

    Then extend the select in `app/(dashboard)/uploads/page.tsx` to include `processing_started_at`
    and `processing_attempts`, and pass an evaluation instant into `mergeHistory`. Take that instant
    once, before the merge, and use it for every row.

    This select is the quiet failure mode of the whole feature: these two columns are new, the
    accessor is untyped, and PostgREST will simply not return a column that is not asked for. A
