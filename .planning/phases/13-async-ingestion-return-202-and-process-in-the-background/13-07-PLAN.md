<objective>
Give the system the trigger that does not depend on anyone's browser, stop the automated path from
having the same disease the manual one had, and give a file that never finishes somewhere to be seen.

D-01 chose two triggers deliberately: an immediate one when the file is accepted, and the daily drain
sweep for everything else — a dropped invocation, a crash, a file whose trigger never fired. D-09 then
noticed that the drain's own per-object ingestion has exactly the problem this phase exists to fix: it
runs the whole pipeline inside a request bound by the same measured ~30-second ceiling, invisible only
because nobody watches a spinner for it. And D-03 requires that a pending row which never completes be
surfaced, because this phase is what makes pending routine and five such rows already sat unnoticed for
up to three days.

Purpose: ROADMAP SC-3, SC-4 and SC-5. Convergence that does not depend on a browser, an automated path
that is no longer quietly at risk, and loudness when convergence does not happen.

Output: the drain's per-object step firing the background function, a bounded sweep inside the one
existing daily job, a stuck-pending group in the grouped Slack alert, and the stuck count on the
evidence row.
</objective>
