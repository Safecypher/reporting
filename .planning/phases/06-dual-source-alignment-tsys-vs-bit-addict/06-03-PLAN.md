<objective>
Complete the comparison: add the two card-flow metrics and the hardest one — **calculated live
cards** — so `/alignment` shows all four metrics side by side for the active period, each with
variance, coverage, tolerance and a verdict.

Purpose: live cards is the metric this phase exists to get right and the easiest one to get
confidently wrong. It is a cumulative running total with no snapshot to anchor it, so a single
uncovered day upstream silently understates every later day by a plausible amount, and the permanent
pre-window offset would read as a mismatch forever if the badge judged the level rather than the
change. Both failure modes are designed against explicitly here: a running coverage guard over the
whole data window, and a gap-change verdict with two always-visible captions that say what the number
is and what its badge means.
Output: migration 0030 applied live, the four-card `/alignment` page reading the real tolerance and
baseline offset, and a read-only SQL oracle proving the guard actually poisons downstream days.
</objective>
