> Visual and interaction contract for Dual-Source Alignment: TSYS vs Bit Addict. Generated by
> gsd-ui-researcher, verified by gsd-ui-checker.

## Design Aesthetic (Decision)

**Decision:** Unchanged — clean, professional, trustworthy internal-tool aesthetic, Cypher Blue as
the single lead, 1pt hairlines over shadows, pill buttons, calm neutrals so colour carries meaning.
Phase 6 introduces one genuinely new visual problem: **a single card must carry two figures, a
variance, a coverage fact, and a verdict without reading as cluttered or alarming.** The answer is
strict internal hierarchy inside the card — the status badge is the one thing colour is allowed to
carry; the two raw figures stay neutral ink; the delta/coverage lines are de-emphasised by size and
muted ink, never by a second colour. This is the same "colour carries meaning, not decoration"
principle Phase 4 established for the reconciliation tables, applied inside a card instead of a
table row.

**Rationale:** Roadmap success criterion 5 requires a genuine disagreement to be visible without
opening the reconciliation page — that only works if the four paired cards read calmly enough on
`/alignment` and on the home page's status strip that a real problem still stands out. A card that
tries to look "busy" to justify its density would bury the one signal that matters.

**Paired KPI card internal hierarchy (binding, the core of this phase's visual contract):**
1. **Status badge** — top-right of the card header, the only coloured element on the card face.
2. **The two figures** — side by side, neutral ink (`--fg-1`), never colourised by source.
3. **Delta / which-side-short phrase** — one line, muted (`--fg-2`), below the figures.
4. **Coverage statement** — one line, quieter still (`--fg-3`), below the delta phrase.
5. **(Live cards only) the permanent derivation caption and the status-meaning caption** — both
   `--fg-3`, at the very bottom of the card, always rendered (never a hover/tooltip reveal).

## Interaction & State Contract (trust-critical)

Every new data surface (`/alignment`'s four cards, the home page's strip and three tiles) keeps
the **same 4-state contract as every prior phase** — loading / empty / populated / error — plus
the period-empty value from Phase 5 where the surface is period-scoped. No exceptions.

**Paired KPI card — status/coverage binding rules:**
- A card's badge colour is **fully determined by the status enum** computed server-side (`aligned`
  / `needs_review` / `mismatch`) — the UI never infers colour from the delta sign or magnitude
  directly (L-04, unchanged from Phase 4's binding rule).
- **Incomplete coverage forces `needs_review` regardless of variance size** (D-12) — the coverage
  line's "Incomplete coverage — treated as needs review" clause and the badge must always agree;
  a card can never show `Aligned` while its own coverage statement admits a gap.
- **Percentage suppression (D-14):** when the Bit Addict figure is zero, render the glyph `—`
  (em dash) in place of the percentage, wrapped with an accessible label that states the reason —
  e.g. `<span aria-label="Percentage not applicable — Bit Addict recorded zero for this metric">—</span>` —
  never a tooltip-only explanation, so the reason is in the accessibility tree unconditionally, not
  behind hover/focus.
- **Live cards' badge answers a different question (D-07, must be visually unmistakable):** its
  status reflects the *change* in the TSYS/Bit Addict gap, not the gap's size. The status-meaning
  caption (see Copywriting) is **always rendered on this card specifically** — not a shared
  footnote — so a viewer cannot read this badge the same way as the other three cards' badges.
- **The live-cards derivation caption (D-08) is permanent, inline, always visible** — never a
  tooltip. It sits directly under the TSYS figure, distinct in position from the status-meaning
  caption (which sits near the badge), so the two captions answer two different questions
  ("what is this number" vs "what does this badge mean") without merging into one paragraph.
- Live cards is a **stock** metric evaluated as-at the period end, mirroring `/cards`' P-02
  rule (L-02) — its coverage/derivation captions should read "as at {period end date}" using the
  same carried-forward phrasing `/cards` already established, not a flow-window phrasing.

**Two-level drill contract (the interaction this phase adds — binding on the pattern, not the
exact URL param names, which are the planner's call per 06-CONTEXT.md):**
- The alignment drill is **one continuous `Sheet`** across both levels — opening level 2 from a
  level-1 row does **not** close and reopen the Sheet; it swaps the Sheet's body content and
  header title in place, exactly like a Sheet-scoped navigation, not a new modal.
- **Level 1** (opened from a card's badge or its "day by day" link) shows the per-day breakdown
  table for that one metric across the active period: day, TSYS figure, Bit Addict figure, delta,
  coverage, status — one row per day, using the same compact `StatusBadge` per row (reuse the
  existing row-tinting convention, `reconciliationStatusToRowClassName`, generalized to the three
  alignment statuses).
- Clicking a day row opens **level 2** for that specific day: two labelled tables (`TSYS rows` /
  `Bit Addict rows`), each captioned with its originating source file name (D-19/SC4, satisfied
  explicitly via the "From {file_name}" caption in Copywriting — never left implicit in a tooltip
  or omitted).
- **Navigating back up** uses an explicit `← Back to day breakdown` affordance at the top of the
  level-2 body — clicking it returns to level 1 for the same metric and period, never closing the
  Sheet. Closing the Sheet outright (✕, Escape, outside click) from **either** level clears the
  whole alignment drill state and returns to the plain `/alignment` URL, matching the existing
  `DrillSheet`/`ReconciliationDrillSheet` close behaviour.
- The Sheet header always states which level is open (see Copywriting's two title formats) — a
  user must never be able to tell from the header alone whether they are looking at a day-by-day
  summary or raw contributing rows only by scanning the table below it.

**Home alignment-strip rollup (the discretion item this phase resolves):**
- **Worst-status-wins severity** determines the strip's single rollup badge: any `mismatch` among
  the four metrics wins over any `needs_review`, which wins over all four being `aligned`.
- The rollup badge is **never shown alone** — it always sits beside the one-line rollup sentence
  (naming which metrics, per Copywriting) **and** the row of four per-metric mini-badges, so a
  viewer can see both "are we OK overall" and "which metric, specifically" without navigating away
  — this is what makes success criterion 5 true on the home page itself, not just on `/alignment`.
- **Before any comparison can be computed** (e.g. first run, before any TSYS or Bit Addict data
  exists for the period), the strip renders the explicit neutral "not yet available" state — it
  must never default to a green `Aligned` badge just because there is nothing to disagree about
  yet; an unearned "all clear" is the exact failure mode PROJECT.md's core value exists to prevent.

**Home KPI tiles:**
- Each tile is a **full page navigation** (`Link`, not `DrillableMetric`) to its canonical page
  (`/cards`, `/verifications`, `/revenue`) — these are read-only duplicates for at-a-glance
  scanning, not a same-page drill, so clicking commits to leaving the home page.
- `Live cards` is unscoped by period (stock metric, L-02); `Volume this period` and `Revenue this
  period` are scoped to the home page's own active period selection, exactly like every other
  period-lens page.

**`/settings/general` contract (extension):**
- The new "Dual-source alignment" section follows the exact pattern 05-UI-SPEC.md set for the
  FY-start field: an always-visible inline scope-impact notice (not a dialog), audited on save,
  appearing at the top of the shared `Change history` log immediately after a successful save.
- Field-level validation (non-negative integer) shows inline errors before submit where possible;
  a rejected submit shows the same banner-error pattern as the FY-start form.

Focus rings (brand `--focus-ring`) visible on all new interactive elements (paired-card
drill-triggers, the "← Back to day breakdown" affordance, home KPI tile links, the two new
settings inputs) — unchanged rule from every prior phase.
