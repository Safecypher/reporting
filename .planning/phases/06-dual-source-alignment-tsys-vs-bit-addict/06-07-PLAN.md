<objective>
Close **CR-01**, **WR-01** and the SQL half of **CR-02** at their source: replace the single
shared, cross-contaminated Bit Addict freshness bound that currently decides `settled` for all
three flow metrics with two named, independently-testable SQL predicates, mirror them in
TypeScript, and extend both existing SQL oracles so divergent per-side freshness is exercised
deliberately with literal arguments rather than hoped for in today's sparse live data.

Purpose: a premature `Mismatch` is a false alarm dressed as certainty. D-02/D-03 deliberately
accept "a genuine problem sits amber for three days" so real catch-up data has time to arrive;
the current shared bound can silently shrink that window to zero for whichever metric's true
counterpart is the stale one. That is the exact "confidently wrong" failure class this whole
phase exists to prevent, on a feature whose stated purpose is trust.

Output: `supabase/migrations/0031_alignment_per_source_settling.sql`, three new exports in
`lib/dashboard/alignment-status.ts`, `lib/dashboard/__tests__/alignment-settled.test.ts`, and
three new assertion blocks across the two existing oracle files.

**Forward-only.** Migrations 0027 through 0030 are already applied to the live database and are
NOT edited. 0031 replaces the objects they declared.
</objective>
