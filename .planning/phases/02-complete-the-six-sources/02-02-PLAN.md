<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → ingest() | Untrusted billing CSV bytes; financial data feeding revenue reconciliation |
| ingest() → Postgres | Normalised rows written server-side with the secret key |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-B1 | Tampering | `authorised` boolean coercion | mitigate | Zod `z.enum(["True","False"])` + `=== "True"` comparison; declined rows stored as false (Pitfall 4) — a wrong-direction bug is caught by the ~16/~78 test tripwire |
| T-02-B2 | Repudiation / Integrity | cumulative re-upload inflating totals | mitigate | UNIQUE(transaction_id) + ON CONFLICT DO NOTHING via `ignoreDuplicates:true` (D-07); idempotency asserted in test (Pitfall 5) |
| T-02-B3 | Information Disclosure | new billing_transactions table readable by anon | mitigate | RLS enable + select-only-authenticated policy in the same migration (carry 0004 forward) |
| T-02-B4 | Tampering | CSV formula/content injection in numeric/timestamp fields | mitigate | Zod type validation rejects non-conforming values; parsed data only ever written to Postgres columns, never re-rendered to a spreadsheet this phase |
| T-02-SC | Tampering | npm installs | accept | No new packages (papaparse+zod already installed/audited) |
</threat_model>
