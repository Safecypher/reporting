## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| migration → live Postgres | Schema + RLS changes applied to the hosted project |
| authenticated client → new tables | Must be select-only; all writes are server-side with the secret key |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-P1 | Information Disclosure | new tables reachable without RLS | mitigate | Each 0006-0010 migration enables RLS + a select-to-authenticated policy; verified via Supabase advisors after push (no missing-RLS warnings) |
| T-02-P2 | Elevation of Privilege | client insert/update/delete on new tables | mitigate | No insert/update/delete policy on any new table for `authenticated`; writes only via the secret-key server client (bypasses RLS) — mirrors 0004 precedent |
| T-02-P3 | Repudiation | false-positive "done" without the push | mitigate | This plan is the mandatory push gate; verification requires tables actually present in the live project, not just green types/tests |
| T-02-SC | Tampering | npm installs | accept | No new packages |
</threat_model>
