| ingest() → ExcelJS | First XLSX parse path; internal XML parsed by saxes |
| ingest() → Postgres | Server-side write with secret key |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-A1 | Denial of Service | zip-bomb / oversized XLSX via `workbook.xlsx.load` | mitigate | 5MB compressed-size cap in route.ts bounds input; wrap `xlsx.load` in try/catch → clean file rejection (never unguarded crash), matching CR-01 |
| T-02-A2 | Information Disclosure / DoS | XML entity expansion (XXE) in the XLSX internal XML | mitigate | ExcelJS parses via saxes which does not resolve external entities by default; stay on exceljs 4.4.0; confirm no external-entity resolution during implementation (one-line check) |
| T-02-A3 | Tampering / EoP | prototype pollution (CVE-2023-30533 class) | mitigate | Use ExcelJS specifically (unaffected); never introduce xlsx/SheetJS npm as a "quick fix" for any XLSX edge case |
| T-02-A4 | Integrity (silent data loss) | dropping hidden rows | mitigate | Parser MUST NOT check row.hidden; test asserts 46 rows (Pitfall 1) — hidden rows are leftover AutoFilter UI state, all are real call events |
| T-02-A5 | Spoofing | classifying by filename instead of sheet structure | mitigate | apigee classify matches only on sheet-name 'APIGEE Calls' + exact 3-column header (D-11); filename ignored |
| T-02-A6 | Information Disclosure | apigee_calls readable by anon | mitigate | RLS enable + select-authenticated policy in 0010 |
