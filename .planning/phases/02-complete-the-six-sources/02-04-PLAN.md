<objective>
Vertical slice: the card-inventory daily-snapshot report parses, derives its snapshot `report_date` from the filename, normalises the naive enrolment timestamp to UTC, de-duplicates on `(report_date, external_card_reference)`, and ingests end-to-end.

Purpose: The snapshot date must come from the filename because `CreatedAt` is enrolment time, not the snapshot day (D-02). Getting this wrong (defaulting to upload time) silently corrupts the Phase 4 live-count/day-over-day diff — so a missing filename date is a hard reject, not a guess.

</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-C1 | Integrity | report_date silently defaulting to today | mitigate | extractReportDateFromFileName returns null → file rejected with a reason (D-02, Pitfall 2); asserted in test — prevents false new snapshots |
| T-02-C2 | Tampering | client-controlled fileName driving report_date | mitigate | file-date.ts round-trip-validates the date (rejects impossible calendars); dedup key includes report_date so a spoofed date can only create/replace that day's snapshot, never corrupt others; raw_created_at retained for audit |
| T-02-C3 | Information Disclosure | card_inventory readable by anon | mitigate | RLS enable + select-authenticated policy in 0008 |
| T-02-SC | Tampering | npm installs | accept | No new packages |
