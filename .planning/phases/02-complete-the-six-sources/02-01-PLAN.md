<objective>
Generalise the verification-hardcoded ingestion core into a per-report-type `ReportHandler` registry, without changing verification's observable behaviour. This is the shared foundation every Phase 2 report slice plugs into.

Purpose: The five new report parsers must be pure additions (one self-contained handler module + one migration + one test each) that never edit shared orchestrator files — enabling them to be built and executed in parallel. That is only possible if `ingest()`, `classify()`, `types.ts`, and the writer are generalised once, here, first.
Output: A registry-driven `ingest()` where verification is one handler among six; five stub handlers (real classification signatures per D-11, `parse()` throwing "not implemented yet") ready for their slices to overwrite; a format-aware header/sheet signature extractor; a generic `upsertRows` writer dep; a shared filename-date helper. Full existing Phase 1 test suite stays green (regression gate).
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → /api/ingest | Uploaded file bytes + client-supplied `fileName` and `contentType` are untrusted |
| ingest() → ExcelJS/PapaParse | Raw bytes are decoded/parsed here (first XLSX code path reached via extractHeaderSignature) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Spoofing | extractHeaderSignature format detection | mitigate | Detect XLSX by ZIP magic bytes (0x50 0x4b) on the buffer, never trust client `contentType` (RESEARCH.md Pitfall 3) |
| T-02-02 | Denial of Service | ExcelJS `workbook.xlsx.load` on a crafted/zip-bomb XLSX during classification | mitigate | Runs after the existing 5MB compressed-size cap in route.ts; wrap the classification-time load in the same defensive try/catch that yields a clean classify-to-null on failure — never an unguarded throw |
| T-02-03 | Tampering | Stub handlers reached before their parser exists | accept | parse() throws a clear reason converted by CR-01 to status:'failed'; no data written; resolved when each Wave 2 slice lands |
| T-02-SC | Tampering | npm/pip/cargo installs | accept | No new installs this plan — exceljs@4.4.0 already present and audited [OK] in RESEARCH.md Package Legitimacy Audit; confirm `node_modules/exceljs` exists, do not reinstall |
