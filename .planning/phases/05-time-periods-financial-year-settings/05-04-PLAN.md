<objective>
Replace the placeholder rates with the real contract and make the tier editor able to correct it.
Two migrations: `0025` loosens the three interlocking Phase-3 guards so a tier set can be edited
in place and any set can be deleted (D-17, D-19), while adding the one genuinely new guard this
phase must not skip — a data-window coverage check, because `v_revenue_tier_set_by_day`'s
`cross join lateral ... limit 1` silently drops a day with no effective tier set instead of
erroring, and loosening delete and backdating is exactly what makes that reachable. `0026` deletes
the placeholder and seeds the signed TSYS MSA six-tier table (D-14, D-15, D-16). Then the pricing
editor gains a tier-set selector, in-place editing, an audited restate warning, and a generalised
delete.

Purpose: ROADMAP SC4 — the TSYS tier table exists as a `pricing_tier_sets` row with
`reset_window = 'monthly'` and the MSA's own worked example (1.5M transactions in a month =
$45,450) matches to the cent. Until this lands, every revenue figure in the product is priced off
invented placeholder rates. Per L-02 the TSYS table is a **data seed, not new schema**: the
existing `pricing_tier_sets.reset_window = 'monthly'` already models the MSA's monthly-in-arrears
reset and `0012_v_revenue.sql` already does the marginal-bracket maths, so no new tier structure
is introduced — only the correct rows and the ability to correct them. L-01 still binds: all money
maths stays exact `NUMERIC` inside `security_invoker` Postgres views and functions, rounded once
at display.
Output: migrations 0025 and 0026, an executable SQL assertion file, the extended Server Actions,
and the corrected pricing editor.
</objective>

<planner_decisions>
- **P-03 — `save_pricing_tier_set` is replaced by a four-argument function, not overloaded**
  (RESEARCH open question 3, resolved). Adding `p_tier_set_id uuid default null` alongside the
  existing three-argument function would leave two candidates matching a three-named-argument
  PostgREST call, which resolves to a PGRST203 ambiguity error at runtime rather than a compile
  error. The migration therefore drops the three-argument function and creates the four-argument
  one, re-issuing the `revoke`/`grant` triple. One call site, one guard implementation.
  Reversibility: costly — the RPC name is a public PostgREST surface and the drop/create pair is
  what the type regeneration in plan 05-05 picks up.
- **P-04 — Restate-dialog thresholds** (closing the case the UI-SPEC recorded as unspecified).
  `N = 0` means no already-elapsed day changes, so the dialog does not appear at all and the save
  proceeds immediately. `N = 1` renders `1 day`, not `1 days` — the copy branches on the count
  rather than relying on the `{s}` shape. Reversibility: reversible.
- **Data-window guard semantics.** The guard raises only when coverage of 2026-08-13 existed
  **before** the operation and would not exist **after** it. A database that already has no
  covering set stays correctable rather than being locked into its gap by a guard added later.
</planner_decisions>

| tier_order | upper_bound | rate |
|---|---|---|
| 0 | 500000 | 0.0405 |
| 1 | 1000000 | 0.0279 |

`effective_from = 2026-08-13`, `reset_window = 'monthly'`. Bands are marginal, not flat; the
monthly volume band resets every month, assessed in arrears; boundaries step by one transaction.

Existing schema this plan changes (`0011_pricing_tiers.sql`):

```
pricing_tier_sets(id uuid pk, effective_from date not null, reset_window text
                  check in ('monthly','quarterly','none'), created_by uuid, created_at timestamptz,
                  constraint pricing_tier_sets_effective_from_key unique (effective_from))
pricing_tiers(id bigint, tier_set_id uuid -> pricing_tier_sets on delete cascade,
              tier_order int, upper_bound bigint NULL only on the last tier,
              rate numeric(12,4), unique (tier_set_id, tier_order))
pricing_tier_audit(id bigint, tier_set_id uuid NULL on delete set null,
                   changed_by uuid, changed_at timestamptz, summary text not null)
trg_pricing_tier_sets_audit  -- AFTER INSERT only; the UPDATE path must write its own audit row
trg_validate_pricing_tier_set -- DEFERRED constraint trigger, re-validates the whole set at COMMIT
```


`p_tiers` keeps its existing jsonb array shape: `[{"tierOrder": int, "upperBound": bigint|null,
