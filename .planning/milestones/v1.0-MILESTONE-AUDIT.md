than assumed. The status matrix keys on a VERIFICATION.md status of `passed`,
`gaps_found` or `missing`. These two phases are at `human_needed`, which is none
of those: verification ran, found no code gaps, and stopped for human
confirmation. Three independent sources agree the work exists —
`requirements-completed` frontmatter in every relevant plan SUMMARY, an explicit
✓ SATISFIED row with evidence in each phase's VERIFICATION.md, and a live

## Cross-Phase Integration

**No blocking gaps.** Seams verified at real call sites, not by import presence:

- **Period lens reaches everything.** All eight data-bearing pages call the same
  `resolvePeriod(params, fyStart, now)` fed by the same `fetchFinancialYearStart`.
  No view computes its own bounds — which is what Phase 5 set out to guarantee
  and Phase 8's WR-03 clamp now enforces in one place.
- **Pricing authority is consistent across three independent consumers.**
  `v_revenue_tier_set_by_day` (actuals), `pricing_tier_set_effective_on`
  (forecast) and `restate-scope.ts` (admin UI) all apply the same "latest
  `effective_from` ≤ day" rule, and `price_volume_through_tier_set` is the single
  marginal-bracket formula behind both Phase 3's actuals and Phase 7's forecast —
  verified identical to 20 significant digits across migration 0039.
- **Reconciliation reads the tables ingestion writes.** No parallel data path;
  the settling-window logic in SQL mirrors `reconciliation-status.ts`.
- **Auth is one choke point.** `proxy.ts`'s matcher was regex-tested directly:
  `api/ingest`, `set-password` and every `(dashboard)` route are gated; only
  `login` and `auth/confirm` are excluded. Every route added by Phases 3–8 was
  covered automatically. RLS is confirmed enabled on all 12 data tables as an
  independent second layer.
- **Drill-down closes the loop** across five pages via shared `drill-params.ts`.
- **Alignment reaches back** into the home dashboard and the reconciliation
  page's APIGEE cross-check, rather than sitting in its own silo.

### Warnings (non-blocking)

**WR-07 — data-window floor duplicated in 8 places.** `lib/dashboard/data-window.ts`
is the single source of truth for the dashboard cluster, but the six
`lib/ingestion/normalise-*.ts` modules each hardcode their own
`Date.parse("2026-08-13T00:00:00Z")`, and SQL has `data_window_start()`. All
eight agree today and this was a documented 08-01/08-04 decision — but changing
the floor means changing eight things, and missing one would silently admit or
exclude the wrong days. Affects DATA-06.

**WR-01 — FY partial-coverage caption.** The FY branch clamps `start` to the data
window, so no figure is ever computed over unreliable days. But nothing on screen
says the range shown is narrower than the FY label implies, so a reader could take
a partial-year figure for a full-year one. Already tracked as a pending todo.
Affects FY-01, PERIOD-01.
