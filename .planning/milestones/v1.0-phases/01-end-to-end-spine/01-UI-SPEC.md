# Phase 1 — UI Design Contract

> Visual and interaction contract for the End-to-End Spine phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker, then **rebased onto the imported Safecypher brand** in `design-system/`.
>
> **Scope:** login screen (AUTH-01/02/03), authenticated app shell + auth boundary, drag-and-drop upload surface with per-upload result feedback (INGEST-01/02/04), and the verifications-over-time dashboard view (DASH-01/04).
>
> **Standing contract:** The tokens below are **not** invented here — they are the imported Safecypher Design System (`design-system/colors_and_type.css`), which is the single source of truth for **all** phases (revenue, SLA, reconciliation). This spec maps that brand onto the Phase 1 surfaces and the shadcn/ui component layer. Where the brand base palette does not define something a data dashboard needs (e.g. a colour-blind-safe second chart series), the addition is called out explicitly as a decision.

> **⚠ Revision note:** This spec was originally approved (2026-08-18) against reasoned placeholder tokens (Geist Sans/Mono, shadcn slate + blue-600) because no brand existed at approval time. It has since been rebased onto the real brand. The Color, Typography, Spacing, and Design System sections changed materially; re-verification via `/gsd:ui-phase 1` (Skip → checker) is recommended before Phase 1 execution.

## Design Aesthetic (Decision)

**Decision:** Clean, professional, trustworthy internal-tool aesthetic carrying the Safecypher identity — Cypher Blue as the single lead, restrained neutrals, EB Garamond reserved for occasional accent headlines. Light theme first. Prioritise data density, legibility, aligned numerics, and calm neutrals so colour carries *meaning* (authenticated vs failed, OK vs discrepancy) rather than decoration. The brand's own preference for **1pt hairlines over shadows** and **pill buttons** is retained.

**Rationale:** PROJECT.md describes an internal reconciliation tool for a small technical team where the core value is *trustworthy* revenue reconciliation. The imported brand already encodes restraint (one lead colour, hairline rules, semantic colour reserved for state) — this suits an operator dashboard, so the spec adopts it directly rather than re-deriving a parallel system.

## Visual Hierarchy & Focal Points

Each screen has one declared primary visual anchor so the executor does not have to guess where the eye should land.

| Screen | Primary anchor (focal point) | Secondary anchors | Tertiary / chrome |
|--------|------------------------------|-------------------|-------------------|
| Login | The sign-in `card` centred in the viewport, with the `Sign in` primary (Cypher Blue, pill) button as the action focus; Safecypher logo above | Heading `Sign in to Safecypher Reporting` | Muted helper text, background |
| Upload surface | The drag-and-drop zone (largest interactive surface, dashed hairline border, centred prompt) | Post-upload result summary card (accepted / duplicates / rejected) | Uploads history table below |
| **Verifications-over-time dashboard** | **The time-series chart** (authenticated vs failed over time) — largest element, top of content, the reason the screen exists (DASH-01) | The KPI **metric** cards (big Cypher-Blue number with 2px underline — brand `.metric` treatment) as a secondary summarising row | The `Daily/Weekly/Monthly` toggle, the `Data as of last import` badge, and the data-window caption are supporting controls/meta |

**Verifications dashboard layout intent:** chart occupies the dominant upper region as the single focal point; the KPI **metric** values (Poppins Bold, Cypher Blue, 2px blue underline per the brand metric treatment; accent-teal underline variant for a single highlighted stat) form a secondary summarising band; the granularity toggle sits adjacent to the chart title; freshness badge and data-window caption are quiet meta near the header. Colour emphasis lives in the chart series — surrounding chrome stays neutral so the data reads first.

## Spacing Scale

Brand 4/8 scale (`design-system/colors_and_type.css`, `--space-1`…`--space-9`). All multiples of 4:

| Token | Value | Usage |
|-------|-------|-------|
| `--space-1` | 4px | Icon-to-label gaps, inline chip padding |
| `--space-2` | 8px | Compact element spacing, badge padding |
| `--space-3` | 12px | Dense table cell padding, tight stacks |
| `--space-4` | 16px | Default element spacing, card inner padding |
| `--space-5` | 24px | Section padding, gap between cards |
| `--space-6` | 32px | Layout gaps, page content padding |
| `--space-7` | 48px | Major section breaks, empty-state vertical rhythm |
| `--space-8` | 64px | Page-level top spacing / header offset |
| `--space-9` | 96px | Generous hero-less top rhythm on sparse screens |

**Note:** 12px (`--space-3`) is now a first-class token (dense reconciliation tables use it for vertical cell padding — this replaces the earlier "exception"). Minimum interactive control height 32–36px; desktop internal tool, so 44px touch targets are **not** required.

## Radius & Shadows

Brand tokens (`--radius-*`, `--shadow-*`). The brand deliberately **prefers 1pt hairlines to shadows** — use elevation sparingly.

| Radius token | Value | Usage |
|--------------|-------|-------|
| `--radius-sm` | 4px | Focus-ring inset, small chips |
| `--radius-md` | 8px | Inputs, small cards, table containers |
| `--radius-lg` | 14px | Cards, panels (the brand card default) |
| `--radius-xl` | 22px | Large feature surfaces, the CVV-style card |
| `--radius-pill` | 999px | **Buttons and pill badges (brand signature — all buttons are pills)** |

| Shadow token | Usage |
|--------------|-------|
| `--shadow-xs` / `--shadow-sm` | Chips, menus, popovers — rare |
| `--shadow-md` | Modals / dialogs only |
| `--shadow-brand` | Reserved for a hero/callout surface (Cypher-Blue glow) — not general UI |

Default surfaces use **1px `--rule` (#c1c1c1) hairline borders**, not shadows.

## Typography

Brand families and scale (`design-system/colors_and_type.css`). Poppins for UI, EB Garamond for accent.

| Role | Family / Weight | Size | Line height | Usage |
|------|-----------------|------|-------------|-------|
| Accent display | EB Garamond 400 (`--font-accent`) | 28–48px (`--fs-h3`…`--fs-h1`) | 1.04–1.25 | Occasional accent headline (e.g. login welcome, section statement) — used sparingly |
| Metric / KPI | Poppins **700** (`.metric`) | 48–64px | 1.0 | Dashboard KPI values — Cypher Blue with a 2px underline (accent-teal underline variant for one highlighted stat). *Intentional downscale: the brand `.metric` is 96px; reduced here for dashboard density.* |
| h1 | Poppins 500 | 48px (`--fs-h1`) | 1.1 | Page title (rare on internal screens) |
| h2 | Poppins 500 | 36px (`--fs-h2`) | 1.25 | Major section title |
| h3 | Poppins 500 | 28px (`--fs-h3`) | 1.25 | Card / panel title |
| h4 / subtitle | Poppins 500 | 22px / 16px | 1.25 | Sub-section titles, `.subtitle` labels |
| Body | Poppins **300 (Light)** | 16px (`--fs-body`) | 1.6 | Default UI text, descriptions, form fields |
| Body small | Poppins 400 | 14px (`--fs-small`) | 1.5 | Dense table cell values, secondary UI (400 not 300 for legibility at 14px — minor deviation, noted) |
| Eyebrow | Poppins 500, uppercase, 0.12em tracking | 12px (`--fs-micro`) | — | Cypher-Blue section eyebrows (`.eyebrow`) |
| Label / caption | Poppins 500 / 300 | 12px (`--fs-micro`) | 1.4 | Column headers, field labels, `as of` meta, captions (`--fg-3`) |

**Weights in use:** Poppins 300 (body), 500 (headings/subtitles/labels/buttons), 700 (metrics); EB Garamond 400 (accent). This follows the brand — it is deliberately **not** the earlier "2 weights only" rule, which was a placeholder decision.

## Color

Light theme, brand palette (`design-system/colors_and_type.css`). The four leads plus derived neutrals; 60/30/10 in practice.

| Role | Token | Value | Usage |
|------|-------|-------|-------|
| Dominant (~60%) | `--bg-2` / `--bg-1` | `#f8f8f9` / `#ffffff` | App background / card surfaces |
| Secondary (~30%) | `--bg-3`, `--cypher-ink-08/15` | `#f1f1f2`, `#e3e3e4` | Panels, table headers, nav, dividers |
| Lead accent (~10%) | `--cypher-blue` | `#382aff` | See reserved-for list below |
| Ink (text) | `--fg-1` / `--fg-2` / `--fg-3` | `#37373a` / `#5b5b5e` / `#8a8a8d` | Primary / secondary / muted text |
| Hairline | `--rule` | `#c1c1c1` | 1pt borders and dividers |
| Destructive | `--error` | `#c1121f` | Error / rejection state and confirmations only (status-pill error `--error-strong` = `#a4161a`) |

**Semantic-colour tokens:** the status colours are now **named tokens** in `design-system/colors_and_type.css` — `--success` `#0a7a4b`, `--warning` `#8a6d00`, `--error` `#c1121f` (plus `--error-strong` `#a4161a` and `-bg`/`-border` tints), promoted from the brand preview components (`badges.html`, `inputs.html`). Later phases (SLA breach red, reconciliation-OK green, needs-review amber) reference these tokens rather than literals.

**Cypher Blue (`#382aff`) reserved for:** primary buttons (`Sign in`, `Upload report`), the active navigation item, focus rings, text links, eyebrows, and the primary/"Authenticated" chart series. **Never** for: card borders (use `--rule`), body text, generic icons, or decorative fill.

**Cypher Accent teal (`#00ede6`) — special-case emphasis only:** a single deliberate highlight (e.g. one KPI's accent underline `.metric-label--accent`, a "New" badge, selection highlight). It is **not** a chart data series (insufficient contrast on white, too close to blue) and **not** shadcn's generic `--accent` hover colour (that maps to `--blue-tint-08`). Per brand, teal touching blue directly is reserved for the signature CVV moment — avoid elsewhere.

### Data-Visualisation Palette (load-bearing for this and all later phases)

Anchored on brand tokens; a colour-blind-safe amber is introduced for the second series (the base palette has no distinct "failed" hue). Blue/amber pairing, never red/green:

| Semantic role | Value | Source | Used for |
|---------------|-------|--------|----------|
| Authenticated / positive | `#382aff` (Cypher Blue) | brand | "Authenticated" verification series; primary data |
| Failed / attention | `#d97706` (amber-600) | **introduced** (CVD-safe vs blue; brand-adjacent to badge amber) | "Failed" verification series; needs-review (later) |
| Discrepancy / breach / error | `#c1121f` (red) | `--error` token | SLA breaches, confirmed mismatches, rejected-row counts (later) |
| OK / balanced | `#0a7a4b` (green) | `--success` token | reconciliation-OK state (later phases) |
| Neutral / reference | `#8a8a8d` / `#c1c1c1` | brand (`--fg-3` / `--rule`) | reference lines (e.g. 750ms SLA line, Phase 3), gridlines, secondary series |

Chart rules: label axes; show a legend for multi-series; tooltips show exact integer counts with tabular numerals; never rely on colour alone — pair failed/breach series with a distinct label and (where space allows) a shape/pattern or icon in the legend.

## Copywriting Contract

Plain, precise, operator-facing — carrying the brand voice from `design-system/preview/tone-in-ui.html`: **sentence case (never title case), no emoji, no exclamation marks; say what happened and what to do.** Numbers are always explicit (accepted / skipped / rejected) — silent failure is forbidden per INGEST-04 and PITFALLS Pitfall-UX.

| Element | Copy |
|---------|------|
| Primary CTA (upload) | `Upload report` |
| Primary CTA (login) | `Sign in` |
| Login screen heading | `Sign in to Safecypher Reporting` |
| Login helper | `Internal team access only.` |
| Upload zone (idle) | `Drag a report file here, or click to browse` with sub-label `CSV or XLSX` |
| Upload zone (dragging) | `Drop to upload` |
| Upload zone (uploading) | `Uploading and processing…` |
| Upload success summary | `Import complete — {accepted} rows accepted · {duplicates} duplicates skipped · {rejected} rejected` |
| Upload rejected-rows detail | `{n} rows rejected:` followed by a per-reason list (e.g. `12 — missing timestamp`, `3 — invalid date`) |
| Empty state heading (verifications view, no data) | `No verifications yet` |
| Empty state body (verifications view) | `Upload the daily verification report to see authenticated vs failed volume over time.` + inline link `Upload report` |
| Empty state (uploads history) | `No uploads yet. Drag a report file above to get started.` |
| Error state (unrecognised file) | `Unrecognised file. This doesn't match any known report type — check you're uploading the daily verification report (CSV or XLSX).` |
| Error state (upload failed / server) | `Upload failed. The file couldn't be processed — try again, and if it keeps happening, check the file isn't corrupted.` |
| Duplicate-file notice | `This file appears to have already been uploaded on {date}. Re-uploading won't change any totals.` |
| "As of" freshness meta (DASH-04) | `Data as of last import: {timestamp}` |
| Data-window caption | `Excludes data before 13 Aug 2026.` |
| Granularity toggle options | `Daily` · `Weekly` · `Monthly` |
| Series legend labels | `Authenticated` · `Failed` |
| Sign-out control | `Sign out` |

**Destructive actions in this phase:** **None.** Ingested records are immutable (PROJECT.md / DATA-07); corrections are made by re-uploading a corrected file (idempotent de-dup), never by editing or deleting rows. `Sign out` is non-destructive and needs no confirmation. If any destructive control is added later, it requires an AlertDialog confirmation naming the exact action.

## Interaction & State Contract (trust-critical)

Every data surface MUST implement four states — missing any one breaks the "no silent failure / know how current the data is" contract:

1. **Loading** — `skeleton` placeholders (chart + cards), never a blank flash.
2. **Empty** — the empty-state copy above with a clear next action (upload).
3. **Populated** — data with the `Data as of last import: {timestamp}` freshness badge (DASH-04) and the data-window caption always visible.
4. **Error** — the error copy above; the failure is shown, never swallowed.

Upload-specific contract (INGEST-04): after every upload the user sees the accepted / duplicates-skipped / rejected breakdown, with per-reason detail for rejects. Unrecognised files are rejected with the explicit message above (INGEST-02). Focus rings (brand `--focus-ring`, Cypher Blue 35%) are visible on all interactive elements for keyboard users.
