<objective>
Replicate the proven tracer across the remaining four metric views so the period lens is uniform:
revenue, SLA, reconciliation and cards each resolve the same `{period, of, yearMode}` contract,
apply it as an outer predicate on their existing unchanged views, show the same active-scope badge,
and fall to the same period-empty state. Add the one new SQL surface the phase needs — a
parameterised `revenue_total_for_period(p_start, p_end)` function — because PostgREST blocks
aggregate `.select()` calls (PGRST123, already documented in `0017_v_revenue_total.sql`) so a
period-scoped exact-NUMERIC total cannot be expressed client-side, and re-summing in JavaScript
is forbidden by L-01.

Purpose: ROADMAP SC2 ("every metric view accepts the same period scope"), SC3 ("previous periods
show that period's figures") and SC5 ("period scoping never changes the tier maths"). SC5 is
delivered by *not* rewriting anything: the marginal-bracket `c_before` window function and the
reconciliation `bounds`/`settled` CTEs all run over the full unfiltered tables before any outer
`WHERE` reaches the view's output, so filtering the output is structurally incapable of pushing
volume into cheaper tiers.
Output: migration 0024, four period-scoped pages, and range-aware card-inventory fetchers with an
explicit stock-versus-flow rule.
</objective>

<planner_decisions>
- **P-02 — Card inventory period semantics (RESEARCH open question 2 / Pitfall 4), resolved.**
  Card inventory is a **stock** metric; the other four views are **flow** metrics. Binding rule:
  the `Enrolled cards` KPI is the latest snapshot whose `report_date` is **at or before the
  period's exclusive end boundary** — never "the latest snapshot strictly inside the period".
  The enrolment-over-time chart, the removals chart and the removals total are **flow**: they
  include only rows inside `[start, end)`. The latest-snapshot card table lists the as-of-period-end
  snapshot's cards. Consequence, stated deliberately: selecting a past month with no new snapshot
  shows the last known true enrolled count carried forward with its real snapshot date in the
  caption, rather than a misleading `0`. Cards reaches the period-empty state only when there are
  no snapshots at all at or before the period end **and** no removals inside the window.
  Reversibility: reversible (two call sites in `cards/page.tsx`).
- **P-06 — The reconciliation live-card figure stays unscoped.** `v_inventory_live_count` is a
  cumulative stock derived from every snapshot; re-scoping it to a past month would make it a
  different quantity with the same name. It keeps reading the whole dataset and its caption states
  it is an as-of-latest-import figure, consistent with P-02's stock rule. Everything else on
  `/reconciliation` is period-scoped. Reversibility: reversible.
- **Migration numbering.** This plan owns `0024` only. `0025` and `0026` are pre-allocated to
  plan 05-04 so the two Wave-2 plans cannot collide (see `coupling_justified`).
</planner_decisions>
