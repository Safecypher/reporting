<planner_notes>
**The D-12 gate is a `period.ts` export, not an inline comparison at each call site.** Three
surfaces need it (`/revenue`, the home tile, and the chart's gate condition) and
`currentUtcMonthOf` / `currentUtcYearOf` are currently module-private. Exporting a named predicate
is what keeps RESEARCH Pitfall 5 from being re-litigated at each site: `resolvePeriod` returning
successfully is NOT evidence that the period is the current one — it succeeds for every valid past
month and year too.

**`period.ts` must stay date-fns-free.** That module deliberately implements its own UTC-only
helpers because date-fns reads local getters and would silently misdate a UTC period boundary in a
non-UTC process timezone (recorded as a Phase 5 decision in STATE.md). Any new helper here uses
`Date.UTC` / `getUTC*` only.

**The provisional token is an alias, not a new hue (07-UI-SPEC Color, binding).** A forecast is not
an alarm, so it must not compete with the success/warning/error triad for attention. The three
tokens alias `--cypher-ink-70`, `--cypher-ink-30` and `--cypher-ink-04`, which are the same values
as `--fg-2`, `--rule` and `--bg-2` respectively — already-approved neutrals given names that make
the intent explicit in code, exactly as the existing semantic triads alias palette values. Note the
binding prohibition: the projected point figure must NOT use `--cypher-ink-50` / `--fg-3`, which
fails WCAG AA for text at 20px bold on white; that tone stays reserved for captions.

**Home is a one-glance summary and stays one.** When the projection is not computable — wrong
scope, below the threshold, or a failed fetch — the sub-line is simply absent. The "N of 7 days"
explanation lives only on `/revenue` (D-18). Do not add a degraded message to the home tile.
</planner_notes>
