<objective>
Make the two numbers that govern every alignment verdict editable, audited and visible: the **TSYS
live-cards baseline offset** (D-09 — the cards already live before 13 Aug 2026, which explains the
permanent gap between the two live-card counts) and the **alignment tolerance** (D-15/D-16 — a single
global absolute count, default 0, that says how far the two sources may differ and still read as
aligned).

Purpose: both are settings rather than constants for the same reason. The agreed definition of "live
cards" with Thesis is still an open operational item, and nobody yet knows what normal drift looks
like at TSYS volumes — so both must be correctable in the UI, with an audit trail, without a deploy.
Deriving the offset in SQL was rejected because a re-ingestion of the anchor day would silently shift
every historical verdict with nobody seeing it.
Output: migration 0029 applied live, a Zod schema and a never-throws reader, an audited Server
Action, and a Dual-source alignment section on /settings/general carrying its own scope-impact notice
and sharing the existing Change history log.
</objective>
